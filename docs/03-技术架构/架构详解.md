# 技术架构

状态：已确认方向的初始化记录；未实现、未运行验证。依据[原始需求](../01-需求文档/原始需求文档.md)第 3–5、9 节。

## 技术栈与模块

| 模块 | 规划目录 | 技术与职责 |
|---|---|---|
| 网页 | `frontend/` | Vue3、TypeScript、Pinia、Vue Router、Vite、TDesign、Tailwind；中文管理入口 |
| 中央服务 | `backend/` | FastAPI、SQLAlchemy、MySQL；业务资料、任务及决策 |
| 执行节点 | `runner/` | Python、asyncio、Codex app-server；环境准备、执行控制及事件记录 |

新平台三个代码目录已建立，目前只有占位文件，无产品代码。版本随相应模块初始化核对后锁定；不继承 OpenRig 的 npm 依赖、SQLite 业务库或 CI 通过结论。

## 部署与运行边界

中央前后端独立构建，计划通过 Docker Compose 部署；Mac/Linux 节点由本机服务管理器托管。节点主动访问中央，无节点入站管理端口。HTTP 轮询、节点 sqlite3、每次执行一个 app-server、独立 CODEX_HOME 均按阶段验证，不能仅凭配置存在宣称可用。

## 数据与接口

中央维护项目、资源和业务状态；节点保存恢复核对及重传所需记录；凭证不进入任务内容。具体表、API 和运行时协议以阶段规格和实现证据为准，当前不提前生成通用模型或接口清单。

## 关键决定

- 在当前仓库和 `feature/chinese-multihost-baseline` 分支建设，OpenRig 参考代码通过固定 Git 提交追溯，当前工作区仅保留新平台结构。
- 先验证单节点执行基础，再扩展网页闭环；见[阶段 0/A 规格草案](阶段0A执行基础规格.md)。
- 不引入 LangGraph、Celery/Redis 或通用调度框架，复杂度由实际问题驱动。
- 目录职责由根 AGENTS.md 维护，业务功能与实现映射由业务架构维护，本文件记录技术边界。
