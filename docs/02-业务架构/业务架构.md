# 业务架构

状态：初始化后的业务概览，依据[原始需求](../01-需求文档/原始需求文档.md)第 1、5–7 节；不是已实现功能说明。

## 角色

用户在 WebUI 选择项目、团队和 SOP，处理人工事项并审查交付。产品、开发、测试、运维是团队职责，不意味着四个常驻进程。独立角色会话与主 agent/subagent 的执行方式仍需决定。

## 主业务流程

| 步骤 | 输入与结果 |
|---|---|
| PROC-1 接入项目 | 确定项目资料与代码所在位置 |
| PROC-2 使用标准团队 | 确定本项目需要的职责组合 |
| PROC-3 选择 SOP | 绑定流程版本、任务目标和适用规则 |
| PROC-4 确认执行安排 | 默认项目电脑可调整，绑定此次节点和工作区 |
| PROC-5 执行与处理人工事项 | 查看有来源的进度；区分业务决定与运行时权限 |
| PROC-6 审查交付 | 查看代码、产物和验证证据；用户验收独立记录 |

## 功能树与实现映射

项目管理、资源管理、团队/SOP、执行控制、人工处理、交付审查均尚未实现；当前不填写不存在的源文件路径。随具体功能落地补充叶子节点到代码的映射。

## 数据流与业务规则

中央维护资料与资源版本，节点准备任务所需环境并执行，事件与产物回到中央供网页查看。代码通过 Git 传递，不把整个工作树存入 MySQL。

业务确认不扩大工具权限；在线不代表任务完成，完成不代表验证通过或用户验收。资料迁移失败不切换主写入来源，成功迁移后不长期双写。详细规则与 SOP 以原始需求为准。
